# Grok в Telegram (бот-посредник к вашему аккаунту xAI)

Telegram-бот на Python (aiogram 3, long polling), который пересылает сообщения в API xAI (Grok)
от имени **вашего** API-ключа. Пользователи общаются с ботом в обычном Telegram — VPN им не нужен:
до xAI ходит сервер, а не телефон пользователя.

Возможности:

- обычные текстовые сообщения → ответ Grok (помнит последние ~10 реплик, история в памяти);
- **поиск в интернете и X**: Grok сам решает, когда искать свежую информацию; под ответом — до 5 ссылок-источников,
  стоимость поиска входит в строку `💰`; `/search <запрос>` — искать обязательно;
- `/img <описание>` — генерация картинки (Grok Imagine), приходит фото;
- `/new` — сбросить историю диалога;
- `/myid` — показать свой Telegram ID (работает для всех);
- `/start` — приветствие и список команд;
- `/carousel [N] <тема>` — карусель для Instagram: N слайдов 1080×1080 (3–10, по умолчанию 7) + подпись с хэштегами;
- `/story <тема> [N]` — сторис 1080×1920 (1–10 кадров, по умолчанию 3), текст в безопасной зоне;
- `/storyvideo [сек] <описание>` — короткое вертикальное видео 9:16 (Grok Imagine Video, 1–15 сек);
- `/meme [зверь] [тема]` — мем с милым животным (котик, капибара, енот, шиба, квокка…): картинка + классическая
  подпись белым с чёрной обводкой; кнопки «🔄 Ещё», «✏️ Другая подпись», «📦 PNG»; `story` — 9:16, `/meme5` — пачка из 5;
- `/memevideo [сек] <зверь> <ситуация>` — короткое мем-видео 9:16;
- **референсы**: фото/альбом с подписью `/carousel …`, `/story …`, `/meme …`, `/img …` или ответ командой на фото —
  карусели, сторис и мемы в стиле ваших фото, с вашим товаром/питомцем, или прямо на ваших фото (`bg`); `/ref` — сохранённые фото;
- `/balance` — остаток на счёте xAI; `/setbalance <$>` — задать остаток вручную (только админ);
- после каждого ответа и каждой картинки — строка вида `💰 Стоимость: $0.0123 · Остаток: $8.45`;
- предупреждения админам, когда баланс опускается ниже $5 и ниже $1 (каждое — один раз за пересечение);
- доступ только для пользователей из `ALLOWED_USER_IDS`;
- длинные ответы режутся на части по 4096 символов, показывается «печатает…» / «отправляет фото…»;
- понятные ошибки на русском, отдельное сообщение, если xAI блокирует регион сервера.

Используемые API xAI (по docs.x.ai, октябрь 2026):

| Что | Endpoint | Модель по умолчанию |
|---|---|---|
| Чат | `POST https://api.x.ai/v1/responses` (store=false, история хранится в боте) | `grok-4.7` |
| Поиск в чате | тот же `/v1/responses` с `tools: [{"type":"web_search"},{"type":"x_search"}]` (серверные инструменты) | `grok-4.7` |
| Картинки | `POST https://api.x.ai/v1/images/generations` (`response_format: b64_json`) | `grok-imagine-image-2.0` |
| Стоимость запроса | поле `usage.cost_in_usd_ticks` в каждом ответе (1 $ = 10¹⁰ тиков) | — |
| Тексты карусели | `POST /v1/responses` со structured outputs (`text.format: json_schema`) | `grok-4.7` |
| Фоны слайдов | `POST /v1/images/generations` с `aspect_ratio` `1:1` / `9:16`, `resolution` `2k` | `grok-imagine-image-2.0` |
| Мемы | тот же `/v1/responses` (подпись + сцена, JSON) и `/v1/images/generations` (`1:1`/`9:16`, `1k`) | те же |
| Референсы | `POST /v1/images/edits` (`image` / `images` до 5, base64 data URI) + vision в `/v1/responses` (`input_image`) | те же |
| Видео | `POST /v1/videos/generations` → опрос `GET /v1/videos/{request_id}` | `grok-imagine-video-1.5-lite` |
| Баланс (необязательно) | `GET https://management-api.x.ai/v1/billing/teams/{team_id}/prepaid/balance` | нужен management key |

Модели меняются через переменные `XAI_CHAT_MODEL` / `XAI_IMAGE_MODEL` — код трогать не нужно.

## Шаг 1. Создайте бота в @BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather), отправьте `/newbot`.
2. Придумайте имя и username (должен заканчиваться на `bot`).
3. BotFather пришлёт токен вида `123456789:AA...` — это `TELEGRAM_BOT_TOKEN`. **Никому его не показывайте.**
4. (Необязательно) `/setcommands` → выберите бота → вставьте:
   ```
   start - Приветствие и помощь
   myid - Узнать свой Telegram ID
   img - Сгенерировать картинку
   new - Новый диалог
   carousel - Карусель для Instagram: /carousel 7 тема
   story - Сторис 9:16: /story тема 3
   storyvideo - Вертикальное видео: /storyvideo 6 описание
   meme - Мем с милым зверем: /meme капибара понедельник
   meme5 - Пачка из 5 мемов: /meme5 кот работа
   memevideo - Мем-видео: /memevideo енот опаздывает на работу
   ref - Референсы: ваши фото для стиля/товара/фона
   search - Ответ с поиском в интернете и X
   balance - Остаток на счёте xAI
   ```

## Шаг 2. Создайте отдельный API-ключ xAI

1. Зайдите на [console.x.ai](https://console.x.ai) (может понадобиться VPN — только вам, один раз).
2. Убедитесь, что на счёте есть кредиты (Billing) — без баланса API вернёт ошибку.
3. Раздел **API Keys** → **Create API key**. Создайте **отдельный** ключ именно для этого бота
   (назовите, например, `telegram-bot`), чтобы его можно было отозвать, не трогая остальные.
   По возможности ограничьте ключу доступные модели/эндпоинты (chat + image) и поставьте лимит расходов.
4. Скопируйте ключ (`xai-...`) — это `XAI_API_KEY`. Он показывается один раз.

> Все запросы пользователей бота оплачиваются с вашего аккаунта xAI. Пускайте в бот только тех, кому доверяете.

## Шаг 3. Загрузите бота на bothost.ru

Есть два способа.

**А. Через GitHub (удобно для обновлений).**
1. Создайте **приватный** репозиторий на GitHub и загрузите туда файлы проекта
   (`bot.py`, `requirements.txt`, `Dockerfile`, `.env.example`, `.gitignore`, `README.md`).
   Файл `.env` с настоящими ключами **в репозиторий не кладите** (он в `.gitignore`).
2. На bothost.ru: зарегистрируйтесь → создайте новый проект/бота → тип **Telegram**, язык **Python** →
   подключите GitHub-репозиторий и ветку `main`.
3. Bothost сам соберёт контейнер (в проекте есть `Dockerfile`; если платформа запускает Python напрямую —
   главный файл `bot.py`, зависимости в `requirements.txt`, команда запуска `python bot.py`).

**Б. Через веб-интерфейс.** Создайте проект и загрузите файлы (или архив) через панель bothost.ru.

Точные названия кнопок в панели bothost могут отличаться — ориентируйтесь на «Создать бота» / «Деплой» / «Переменные окружения».

**Бесплатный тариф (Starter):** по описанию на сайте панели env-переменных там нет, а данные стираются
при перезапуске. Вариант — загрузить через веб-интерфейс файл `.env` (скопируйте `.env.example` в `.env`
и впишите значения): бот читает его сам при старте. Делайте так **только** при загрузке через веб-панель
или из приватного репозитория — никогда не публикуйте `.env`. История диалогов в любом случае хранится
только в памяти и сбрасывается при перезапуске (это нормально). 256 МБ RAM боту хватает.

После сохранения переменных перезапустите бота. В логах должно появиться:
`Запущен @имя_бота | chat=grok-4.7 image=grok-imagine-image-2.0 | ...`

## Шаг 5. Узнайте свой ID и откройте себе доступ

1. Напишите своему боту `/myid` — он ответит `Ваш Telegram ID: 123456789`.
2. Впишите это число в `ALLOWED_USER_IDS` (несколько человек — через запятую, пробелы допустимы).
3. Перезапустите бота. Теперь можно писать сообщения и пользоваться `/img`.
4. Чтобы дать доступ другу — пусть он напишет боту `/myid` и пришлёт вам число; добавьте его в список.

## Контент для Instagram

### Карусель — `/carousel [N] <тема>`

Пример: `/carousel 7 как выбрать первую кофемолку`

1. Grok (`grok-4.7`, ответ строго в JSON) пишет: слайд-хук, контентные слайды, слайд с призывом к действию,
   подпись к посту с хэштегами и **один общий визуальный стиль** для всех фонов.
2. Для каждого слайда по очереди генерируется фон `grok-imagine-image-2.0` с `aspect_ratio: "1:1"`,
   обрезается/масштабируется до **1080×1080**, поверх — затемнение, тёмная плашка, текст (шрифт Montserrat),
   номер слайда «3/7», на первом — «Листайте →», на последнем — `BRAND_NAME`.
3. В Telegram приходит альбом, отдельным сообщением — подпись (её удобно скопировать в Instagram),
   затем строка `💰 Итого: $0.3100 (текст + 7 изобр.) · Остаток: $8.14` и кнопка
   **«📦 PNG без сжатия (zip)»** — Telegram сжимает фото в альбоме, а в архиве оригиналы PNG.
   Сразу архивом: добавьте слово `zip` — `/carousel 5 zip тема`. Файлы для кнопки хранятся 1 час (и до перезапуска).

Пока идёт генерация, бот обновляет статус: «🎨 Генерирую слайд 3/7…». Если фон для слайда не удалось получить
(например, модерация), бот повторит запрос один раз, а потом подставит градиентный фон и напишет об этом.

### Сторис — `/story <тема> [N]`

Пример: `/story анонс эфира в четверг 3`. Кадры **1080×1920** (9:16), фон с `aspect_ratio: "9:16"`.
Текст и номер кадра размещаются только в безопасной зоне: сверху отступ 250 px (аватар, полоски прогресса),
снизу 340 px (поле ответа). Флаг `zip` тоже работает.

### Видео — `/storyvideo [сек] <описание>`

Пример: `/storyvideo 6 чашка кофе на подоконнике, пар, утренний свет, камера медленно приближается`.
API xAI генерирует видео асинхронно: бот отправляет запрос (`aspect_ratio: "9:16"`, `resolution` из `VIDEO_RESOLUTION`,
по умолчанию 720p), раз в 5 секунд спрашивает статус и показывает прогресс, потом скачивает MP4 и присылает его
вместе с реальной стоимостью. Модель по умолчанию — `grok-imagine-video-1.5-lite` (по документации — самая дешёвая
за секунду: 480p — $0.02/сек, 720p — $0.03/сек, 1080p — $0.14/сек; рекомендована для простых роликов). В видео есть звук. Лимит Telegram на отправку
файла ботом — 50 МБ.

### Стоимость и баланс

Перед запуском бот считает оценку: тексты (`EST_CHAT_USD`, по умолчанию $0.03) + N × цена картинки по таблице
docs.x.ai (grok-imagine-image-2.0: 1K — $0.04, 1.5K — $0.05, **2K — $0.06**, quality medium — +$0.02; карусель из 7
слайдов в 2K ≈ $0.45), для видео — секунды × цена по разрешению (lite 720p — $0.03/сек; переопределяется `PRICE_VIDEO_PER_SEC`). Если оценка больше известного остатка, бот спросит подтверждение
(кнопки «Всё равно запустить» / «Отмена»). В итоговой строке — **сумма реальных** `cost_in_usd_ticks` всех вызовов.

### Оформление под бренд

`BRAND_NAME=@coffee.lab` — подпись на слайдах и крупно на последнем; `BRAND_STYLE=тёплые бежевые тона, плёночное фото, минимализм`
— добавляется к стилю фонов и ТЗ для Grok; `BRAND_ACCENT=#FFD54A` — цвет акцентов.

Примеры раскладки (фоны-заглушки, без API): `samples/carousel_preview.jpg`, `samples/story_preview.jpg`,
`samples/story_safe_zones.jpg` (красным — зоны интерфейса Instagram). Пересобрать: `python samples/render_samples.py`.

### Память (256 МБ на бесплатном тарифе)

Картинки генерируются и обрабатываются строго по одной, готовые кадры сразу пишутся на диск, видео скачивается
потоково в файл. Одновременно выполняется одна тяжёлая задача (`MAX_PARALLEL_JOBS=1`), остальные ждут в очереди.
После каждого кадра память явно возвращается системе (`gc` + `malloc_trim`). Замер с моками на сторис из 10 кадров
с фонами 2k (1536×2752, JPEG ~4 МБ): в простое ≈108–120 МБ, пик ≈190 МБ (включая сам тестовый мок, который держит
картинку в памяти), после задачи снова ≈121 МБ — запас до 256 МБ есть. Если хостинг всё же убивает процесс,
поставьте `INSTA_IMAGE_RESOLUTION=1k`.
С 4 референсами (по ~1 МБ) в режиме `edit` пик на сторис из 10 кадров ≈200 МБ, в режиме `bg` ≈160 МБ. Версия aiogram закреплена на 3.28.0 —
более новые 3.29–3.31 при импорте занимают на 30–70 МБ больше.


## Мемы с милыми животными

### `/meme [зверь] [тема/ситуация]`

Примеры: `/meme капибара понедельник`, `/meme енот тендеры`, `/meme story котик работа`, `/meme 3 хомяк дедлайн`,
`/meme5 шиба отпуск`. Без зверя (`/meme` или `/meme понедельник`) бот покажет кнопки со зверями и «🎲 Случайный».

Как работает:
1. Grok (`/v1/responses`, structured outputs) придумывает короткую русскую подпись в стиле мема — верх/низ
   (завязка → панчлайн) или однострочник — и сцену для картинки на английском. Юмор жизненный и добрый
   (работа, понедельник, дедлайны, быт), без политики, мата и оскорблений.
2. Grok Imagine рисует фото зверя (`aspect_ratio` `1:1`, со словом `story` — `9:16`; `resolution` из
   `MEME_IMAGE_RESOLUTION`, по умолчанию `1k` — для мема достаточно и экономит память).
3. Бот накладывает классическую подпись: КАПС, белый текст с чёрной обводкой, шрифт **Oswald Bold**
   (Impact-подобный, SIL OFL, полная кириллица; Anton проверяли — кириллицы в нём нет). Размер подбирается сам,
   в формате 9:16 текст стоит в безопасной зоне сторис. `BRAND_NAME` пишется мелко в углу.
4. Под мемом кнопки: **🔄 Ещё** — новый мем с тем же зверем и темой; **✏️ Другая подпись** — новая подпись
   к той же картинке (платится только текст, ≈$0.005–0.01); **📦 PNG** — файл без сжатия Telegram.
   Картинки хранятся 1 час (и до перезапуска).

Пачка: число 1–5 после команды (`/meme 3 кот`) или `/meme5`. Каждый мем приходит отдельным фото со своими
кнопками, в конце — итоговая стоимость. Одна задача на пользователя одновременно, генерация — по одной картинке.

Примерная стоимость (по прайсу docs.x.ai, реальная берётся из ответа): мем ≈ $0.04 (картинка) + $0.005–0.01 (текст);
`/meme5` ≈ $0.21; другая подпись ≈ $0.01.

### `/memevideo [сек] <зверь> <ситуация>`

Пример: `/memevideo 6 капибара сидит на созвоне, который мог быть письмом`. Grok пишет сценку и подпись,
дальше — тот же видеопайплайн, что у `/storyvideo` (9:16, `grok-imagine-video-1.5-lite`, 720p ≈$0.03/сек → 6 сек ≈ $0.18).
Подпись приходит текстом под видео (на сам ролик текст не накладывается).

### Список зверей — `MEME_ANIMALS`

По умолчанию (по результатам поиска трендов 2026 года): котик, капибара, енот, шиба-ину, квокка, выдра, хомяк,
карликовый бегемотик (Moo Deng-стиль), пингвин, обезьянка-макака. Свой список — ключи через запятую и/или свои звери
в формате `Название:описание на английском`:

```
MEME_ANIMALS=cat,capybara,raccoon,🦊 Лиса:a fluffy red fox,🐼 Красная панда:a red panda
```

Ключи: `cat, capybara, raccoon, shiba, quokka, otter, hamster, pygmy_hippo, penguin, macaque`.
В промптах используются обобщённые описания («a round chubby raccoon»), а не конкретные знаменитые животные.

Макеты интерфейса в стиле Telegram (это **макеты**, не скриншоты живого бота; тексты взяты из кода):

## Референсы — ваши фото для каруселей, сторис и мемов

### Как передать фото

- **Фото или альбом с подписью-командой**: `/carousel 7 тема`, `/story тема 5`, `/meme работа`, `/img сделай акварелью`
  (подпись у альбома достаточно поставить на любом фото). Эти фото используются только для этой задачи.
- **Ответ командой на сообщение с фото** — то же самое для одного фото.
- **Просто фото без подписи** — бот сохранит их как ваши референсы (до `REF_MAX`, по умолчанию 4; хранятся 1 час
  в `/tmp`, удаляются при перезапуске). Дальше все `/carousel`, `/story`, `/meme` их учитывают.
  `/ref` — посмотреть (пришлёт превью), `/ref clear` — удалить, слово `noref` в команде — не использовать в этот раз.

Фото уменьшаются до 1536 px по длинной стороне сразу при приёме (JPEG), поэтому на 256 МБ RAM это не влияет.
Можно присылать и картинку файлом (JPG/PNG/WebP до 20 МБ — лимит скачивания Bot API).

### Режимы (`REF_MODE` по умолчанию или слово в команде)

| Режим | Что делает | Цена (оценка по docs) |
|---|---|---|
| `edit` (по умолчанию) | фото передаются в `POST /v1/images/edits` (до 5 исходных картинок): новый фон каждого слайда в стиле ваших фото, с тем же товаром/персонажем/питомцем | картинка 2K·Low $0.06 (`REF_EDIT_QUALITY=medium` — $0.08) **+ $0.01 за каждый референс** в каждом запросе |
| `style` | Grok смотрит на фото (vision) и описывает стиль, палитру и объект; описание добавляется в промпт обычной генерации | как обычная генерация + ≈$0.002–0.01 за описание |
| `bg` | само фото становится фоном слайда/мема (обрезка под 1:1 или 9:16, текст поверх), картинки **не генерируются** | только тексты (≈$0.01–0.03) |

Во всех режимах Grok сначала смотрит на фото (vision, `detail: low`) и учитывает их в текстах и в общем стиле
серии (`REF_VISION=0` — выключить). Если xAI вдруг не примет запрос на `/images/edits` (ошибка 400), бот автоматически
продолжит обычной генерацией с описанием стиля и напишет об этом.

Пример: карусель из 7 слайдов в 2K с 2 референсами в режиме `edit` ≈ $0.03 + 7 × ($0.06 + 2 × $0.01) ≈ $0.59;
в режиме `bg` ≈ $0.03.

### Мемы по вашему фото

- `/meme работа` с фото (или ответом на фото) без зверя — героем мема станет то, что на фото (ваш кот, товар, коллега-кружка):
  в режиме `edit` бот нарисует новую сцену с этим героем, в режиме `bg` — наложит подпись прямо на ваше фото
  (классический мем-генератор, платится только текст). Кнопки «🔄 Ещё / ✏️ Другая подпись / 📦 PNG» работают как обычно.
- `/meme капибара работа style` + фото — капибара в стиле вашего фото.

### `/img` по фото

Ответьте на фото командой `/img сделай в стиле акварели` (или пришлите фото с такой подписью) — бот отредактирует
именно это фото через `/v1/images/edits`.

> Фото уходят в xAI (как и тексты) — не отправляйте боту то, что нельзя показывать третьим лицам.
> Генерация с фото реальных людей может отклоняться модерацией xAI.

Макет: `samples/ui_7_refs.png`.

## Поиск в интернете и X

Обычные сообщения отправляются в xAI вместе с серверными инструментами **Web Search** и **X Search**
([docs.x.ai/developers/tools/web-search](https://docs.x.ai/developers/tools/web-search),
[x-search](https://docs.x.ai/developers/tools/x-search), [обзор](https://docs.x.ai/developers/tools/overview)).
Grok **сам решает**, нужно ли искать: на «как сварить кофе» он ответит сразу (поиск не платится),
на «какая погода на выходных» или «что пишут в X про …» — сходит в интернет/X, прочитает страницы и ответит.
Всё происходит на стороне xAI, бот просто получает готовый ответ.

- Ссылки в тексте xAI возвращает как `[[1]](url)` ([citations](https://docs.x.ai/developers/tools/citations));
  бот превращает их в компактные `[1]`, а под ответом показывает строку
  `🔗 Источники: [1] reuters.com · [2] X @xai · …` — до `SEARCH_MAX_SOURCES` (по умолчанию 5) кликабельных ссылок,
  без превью. Номера совпадают с `[N]` в тексте.
- Строка `🔎 Поиск: веб ×2, X ×1 (постов 12)` — сколько раз Grok искал; стоимость ниже — **реальная**
  (`usage.cost_in_usd_ticks` включает и токены, и вызовы инструментов) с пометкой «(вкл. поиск)».
- Длинный ответ режется на части по 4096 символов; источники и стоимость — всегда в конце последней части
  (или отдельным сообщением, если не влезают).
- В историю диалога сохраняется текст без ссылок — контекст не раздувается.
- `/search <запрос>` — поиск **обязательно** (бот просит модель искать: `tool_choice: "required"` + инструкция).
  Работает и при `SEARCH_MODE=off`.
- `SEARCH_MODE=off` — обычный чат без поиска (дешевле и быстрее). `SEARCH_TOOLS=web` или `x` — только один вид поиска.
  `SEARCH_MAX_TOOL_CALLS=3` — ограничить число вызовов инструментов на ответ (необязательно).
- Если xAI отклонит запрос с инструментами (ошибка 400, например у модели без поддержки tools), бот повторит
  запрос проще, а в крайнем случае ответит без поиска и напишет «Поиск недоступен…».

**Цены** ([docs.x.ai/developers/pricing](https://docs.x.ai/developers/pricing), раздел Tools, октябрь 2026):

| Инструмент | Цена |
|---|---|
| Web Search | $5 за 1000 вызовов (≈$0.005 за поиск) |
| X Search | $5 за 1000 найденных постов, $10 за 1000 профилей (≈$0.005 за пост) |
| + токены | найденные страницы/посты читает модель — это входные токены по цене `grok-4.7` |

На практике ответ с поиском стоит примерно **$0.01–0.15** (чаще всего $0.02–0.05), без поиска — доли цента.
Дороже всего X Search: если модель прочитает 20 постов — это уже $0.10. Если нужно экономить —
`SEARCH_TOOLS=web` или `SEARCH_MODE=off` + `/search` по необходимости.

> Старый способ — `search_parameters` (Live Search) — xAI отключила: такой запрос возвращает 410 Gone.
> Бот использует новый Agent Tools API.

Макет: `samples/ui_8_search.png`.

## Стоимость и баланс (общее)

### Стоимость каждого запроса — реальная

xAI возвращает в каждом ответе (чат, картинки) поле `usage.cost_in_usd_ticks` — это **фактически списанная**
сумма с учётом скидок за кэш ([docs.x.ai/developers/cost-tracking](https://docs.x.ai/developers/cost-tracking)).
Бот показывает её как `Стоимость: $0.0123`.

Если поля вдруг не окажется, бот **оценит** стоимость по токенам и прайсу из переменных `PRICE_*`
(по умолчанию — цены grok-4.7: $2 / $0.50 (кэш) / $6 за 1M токенов; картинка grok-imagine-image-2.0 — $0.04 за 1K, $0.06 за 2K, вход-референс — $0.01)
и пометит её знаком `≈`. Если меняете модель — поправьте и цены.

### Остаток баланса — два варианта

**Вариант А — точный баланс через Management API xAI (рекомендуется).**
1. console.x.ai → **Settings → Management Keys** → создайте ключ (у вашей учётной записи должно быть право
   «Management Keys»; если пункта нет — попросите админа команды). Это **отдельный** ключ, не `XAI_API_KEY`.
   Он даёт широкий доступ к управлению командой (ключи, биллинг) — храните его особенно бережно.
2. Скопируйте **Team ID** команды в console.x.ai.
3. Задайте `XAI_MANAGEMENT_KEY` и `XAI_TEAM_ID` (если Team ID не указать, бот попробует определить его по ключу).

Бот читает остаток предоплаченных кредитов не чаще раза в `BALANCE_REFRESH_SEC` секунд (по умолчанию 60),
а между обновлениями вычитает реальную стоимость запросов сам. Точное значение показывается как `$8.45`,
значение «API минус траты после последнего обновления» — как `≈$8.41`.
Сверьте один раз с console.x.ai → Billing: если цифры заметно расходятся, используйте вариант Б.

**Вариант Б — без Management API: стартовый остаток + счётчик.**
1. Посмотрите текущий остаток в console.x.ai → Billing.
2. Задайте `START_BALANCE_USD=10.00` **или** после запуска отправьте боту `/setbalance 10.00` (только админ).
3. Бот вычитает из этой суммы стоимость каждого своего запроса. Остаток показывается со знаком `≈`:
   бот не видит расходов по этому ключу/команде из других программ, пополнений и т.п. — после пополнения
   снова сделайте `/setbalance`.

Счётчик хранится в файле `DATA_DIR/balance.json` (в Docker по умолчанию `/app/data`).
**На бесплатном тарифе bothost данные стираются при перезапуске** — счётчик вернётся к `START_BALANCE_USD`
(или станет «неизвестен»). Чтобы он сохранялся, нужен тариф **Basic/Pro** с постоянным хранилищем (Volume):
смонтируйте том и укажите путь к нему в `DATA_DIR`. Если папка недоступна для записи, бот работает с учётом
в памяти и пишет об этом в `/balance` и в логах. В варианте А это не важно — баланс берётся из xAI.

### Предупреждения о низком балансе

Когда остаток опускается ниже **$5** и ниже **$1**, бот один раз пишет об этом всем из `ADMIN_USER_IDS`
(по умолчанию — всем из `ALLOWED_USER_IDS`). После пополнения (баланс снова выше порога) предупреждение
«взводится» заново. Пороги меняются через `BALANCE_WARN_THRESHOLDS=10,5,1`. Админ должен хотя бы раз
написать боту `/start`, иначе Telegram не даст боту отправить ему сообщение.
Проверка идёт после каждого платного запроса (и при `/balance`) — бот не опрашивает баланс в фоне.


## Шаг 6. Если xAI блокирует регион сервера

Бот работает так: **Telegram ↔ сервер бота ↔ api.x.ai**. Если сервер находится в России, xAI может
отклонять запросы с российских IP. Тогда бот ответит:
«🌍 xAI отклонил запрос (HTTP 403). Скорее всего, API xAI недоступен из страны, где стоит сервер бота…»
или «📡 Не удалось подключиться к xAI…».

> На главной странице bothost.ru **не указано, в какой стране находятся серверы**. Это стоит уточнить
> в поддержке (support@bothost.ru, @Bothostru) или просто проверить: запустите бота и отправьте сообщение.

Что делать:

1. **`XAI_PROXY`** — арендуйте небольшой прокси за рубежом (HTTP(S) или SOCKS5, лучше с логином/паролем)
   и укажите его, например `socks5://user:pass@203.0.113.10:1080`. Через прокси идут **только** запросы к xAI;
   Telegram бот продолжает опрашивать напрямую. Для DNS через прокси используйте `socks5h://...`.
2. **Зарубежный VPS** — разместите этот же проект (Docker) на VPS в Европе/США: тогда прокси не нужен.
   Запуск: `docker build -t grok-tg-bot . && docker run -d --restart=always --env-file .env grok-tg-bot`.

Если бот вообще не запускается и в логах ошибки соединения с `api.telegram.org` — значит, у сервера проблемы
с доступом к Telegram; это вопрос к хостингу (этот прокси на Telegram не влияет).

## Безопасность

- Ключи (включая management key) и токен в логи не пишутся (они дополнительно маскируются `***`).
- Используйте отдельный ключ xAI с лимитом расходов; при утечке — удалите его в console.x.ai и создайте новый.
- Токен бота при утечке перевыпускается в @BotFather (`/revoke`).
- История чатов хранится только в оперативной памяти и не сохраняется на диск; на сервере xAI ответы тоже
  не сохраняются (`store: false`).
